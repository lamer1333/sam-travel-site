# SAM TRAVEL — аудит 8 октября 2026: находки и что с ними делать

Три независимые проверки: безопасность кода в браузере и Edge Functions (S), безопасность
базы (D), ошибки в работе (B). «Подтв.» — воспроизведено пробой на тестовой базе или
скриптом; «не подтв.» — выведено из кода, нужен живой сервис. Номера строк — на коммит
`2f3a231`, перед правкой сверяться по содержимому.

Этап 10 чинит всё с метками **S** и **D**. Этап 11 — всё с меткой **B**, раздел «Хвосты»
и «Устаревшие тексты». Не публиковать этот файл: в нём описаны незакрытые дыры.

## Решения заказчика

1. Когда в базе нет ни одного опубликованного тура, сайт показывает **одну карточку
   «Спросите нас в WhatsApp»** (EN / RU / HY, с обычной ссылкой и номером обращения), а не
   встроенные образцы. Блоки отзывов и команды при пустом ответе базы **скрываются**.
   Встроенные образцы остаются только на случай, когда база недоступна.
2. Роль «Контент» (SMM) в блоке «Команда» **меняет только фото**: не добавляет, не
   удаляет, не правит имя, должность и WhatsApp сотрудника.

## S — безопасность сайта, панели, Edge Functions (этап 10)

**S1. Высокая. Вредоносная разметка через «Что включено» в описании тура.** Подтв.
`js/app.js:166` — `$('#sheet-inc').innerHTML = t.inc.map(… + s + …)`. Источник —
`tours.i18n.<lang>.inc[]`, пишет роль `content`. Сайт и панель на одном origin, сессия в
localStorage. Чинить: собирать `<li>` через createElement/textContent; `inc` приводить
`Array.isArray`. Плюс в базе: проверка, что `inc` — массив строк ≤ 200 символов.

**S2. Средняя. Формулы в CSV.** Подтв. `js/admin/ui.js` `csv()` — ячейка, начинающаяся с
`= + - @` табуляции или CR, должна получать ведущий апостроф и кавычки. Источники: имя и
телефон клиента при регистрации, `utm_*`, название тура, поля кампаний и промокодов.

**S3. Средняя. Mail.ru-мост** (`supabase/functions/mailru-auth/index.ts`). Не подтв.
- a) нет привязки `state` к браузеру → случайный nonce в `state` и в cookie
  `HttpOnly; Secure; SameSite=Lax`, сверка на возврате;
- b) заранее зарегистрированный неподтверждённый адрес: перед `generateLink` найти
  пользователя; если `email_confirmed_at` пуст — сбросить пароль на случайный; ошибки
  `createUser`, кроме «уже существует», не глотать;
- c) ошибка ведёт на несуществующий `/login.html`; при пустом `SITE_URL` — необработанное
  500; `btoa` вне `try`; токен Mail.ru в строке запроса и сырой текст ошибки в логах;
  переменные окружения не проверяются.

**S4. Средняя. supabase-js с CDN без версии и SRI** (`index.html`, `admin.html`,
`cabinet.html`). Положить точную версию в `js/vendor/`, добавить в `build.mjs`, убрать
`cdn.jsdelivr.net` из `script-src` везде; `cdnjs.cloudflare.com` оставить только там, где
нужен qrcode (у него SRI есть), либо тоже перенести в vendor.

**S5. Низкая.** Адрес фото идёт в CSS без экранирования и с любого https-хоста
(`js/app.js:156`, `js/cms.js:155`, `js/admin/views/content.js:65`). Принимать только
`<SAM_SUPABASE.url>/storage/v1/object/public/media/…` (и `data:image` в демо), та же
проверка CHECK в базе для `photo_url`, `photo_hero_url` у tours/reviews/team.

**S6. Низкая. Заголовки.** `_headers`: правила для `/admin` и `/cabinet` (Cloudflare
отдаёт без `.html`) — `X-Robots-Tag`, `Cache-Control`. GitHub Pages `_headers` не читает:
решение о хостинге принимает заказчик на этапе 6, здесь — только отметить в `DEPLOY.md`.

**S7. Низкая.** `?lang=constructor` и `#checklist/constructor` проходят проверку
(`js/app.js:577`, `:307`) → `Object.prototype.hasOwnProperty.call`.

**S8. Низкая.** Минимальная длина пароля на сайте 6 (`js/app.js:743`), по ТЗ — 10.

**S9. Низкая.** `tours.photo_class` — свободный текст, в панели попадает в селектор `h()`
(`content.js:231, 254, 259`) → CHECK на восемь известных значений. `window.__samPanel`
(`js/admin/main.js:98`) убрать вне демо.

## D — безопасность базы (этап 10, миграция `100_security.sql`)

**D1. Средняя. Менеджер пишет в `coupons`.** Подтв. Осталась политика
`"coupons: staff all"` из 001. Удалить, дать команде чтение (`is_team()`), запись —
`is_marketing()`.

**D2. Средняя. `submit_lead()` доступна `authenticated`.** Подтв.: клиент создаёт заявку,
на неё ставится письмо `kind='lead'`. `revoke … from public, anon, authenticated`;
`notify_claim` не отдаёт `kind='lead'`; удалить уже висящие такие записи.

**D3. Средняя. `track()`: общий потолок — выключатель для всех.** Подтв.: 20 вызовов по 30
событий с новыми `sid` — и настоящий `wa_click` не сохранён. Нужно: лимит на отправителя
(`sender_hash()`, например 120 событий в минуту) перед общим; общий поднять; для
`wa_click` — отдельный запас; `utm_*` и `ref_host` — только `[A-Za-z0-9._~-]{1,60}`;
`promo_id` — строгий шаблон uuid (сейчас 36 дефисов роняют пачку).

**D4. Средняя. Сумма закрытой продажи меняется без записи `money`.** Подтв.: `won →
quoted` с новой суммой, затем `→ won`. В `leads_log` писать строку, когда меняются
`value`/`profit`/`closed_at` и старый **или** новый статус закрытый.

**D5. Средняя. `NaN` проходит денежные проверки.** Подтв.: продажа с `value='NaN'`
превращает отчёты в «NaN». CHECK `value <> 'NaN' and profit <> 'NaN'` на `leads`,
`spend >= 0 and spend <> 'NaN'` на `campaigns`; то же в `leads_guard`.

**D6. Средняя. Повторный запуск одной старой миграции отдельно возвращает дыры и ломает
панель.** Подтв. для 001, 002, 020, 030, 050. Защиту-предохранитель ставить нельзя (тесты
накатывают весь набор дважды). Делать: в заголовках 001–090 и в `SETUP-ADMIN.md` заменить
«повторный запуск безопасен» на «только весь набор по порядку; после повторного запуска
файла N — все следующие»; в этапе 6 накатывать через Supabase CLI.

**D7. Низкая. Номер обращения не привязан к визиту.** Подтв. Считать номер в SQL из `sid`
(портировать `refOf` из `js/track.js`) и игнорировать присланный; в `wa_ref_lookup` брать
метки, тур и промокод только из `sid` последнего клика; промокод из события не
подставлять в продажу молча — показывать в форме как подсказку.

**D8. Низкая. Бакет `media`: менеджер может перезаписать любой файл.** Insert/update —
только `is_marketing() or is_content()`; `on conflict (id) do update` для лимитов бакета.

**D9. Низкая. `content` пишет всю таблицу `team`.** По решению заказчика — только
`photo_url`: политика UPDATE + триггер, запрещающий роли менять остальные поля; без
INSERT и DELETE. `row_history` не должна отдавать email как имя автора — подпись роли.

**D10. Низкая. Нет ограничений длины** у `profiles.full_name` (≤120), `phone` (≤40),
`consent_source` (≤40, список допустимых); в `handle_new_user` — `left()`.

**D11. Низкая.** Менеджер вставляет в историю продажи строки `system` задним числом →
убрать `system` из разрешённых для API, `created_at := now()` триггером.

**D12. Низкая. `check_coupon()` без ограничения попыток** → счётчик по `sender_hash()`,
10 в минуту. (Сайт её не вызывает; оставить закрытой для гостей, если не нужна.)

**D13. Низкая. EXECUTE у PUBLIC**: `set_role`, `row_history`, `restore_version`,
`media_alive`, `work_minutes`, `url_encode`, `reminder_fill`, `reminder_default` →
`revoke … from public, anon`; `alter default privileges … revoke execute on functions
from public`.

**D14. Низкая.** `reels.url` — шаблон без `$` в конце.

**D15. Низкая.** `public_site()` вычитает приватные ключи `company` списком запретов →

`js/admin/api.js` `saveSetting` — upsert, а политика только UPDATE. Делать `update`, и
insert только если строки не было.
