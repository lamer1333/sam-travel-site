# SAM TRAVEL — бэкенд по этапам

Работа из `TZ-BACKEND.md` разбита на 7 этапов. **Один этап — один чат.** Чат начинается с
готового запроса (ниже), заканчивается зелёными тестами и коммитом. Следующий чат ничего
не знает о предыдущем, кроме того, что лежит в репозитории, — поэтому всё важное должно
быть в коде, тестах и в этом файле.

## Правила для каждого чата

1. Сначала прочитать `TZ-BACKEND.md` (особенно §0 «Принятые решения») и свой этап здесь.
2. Не править чужое: SQL — только новым файлом `supabase/migrations/NNN_название.sql`,
   тесты — только своим файлом `supabase/test/NN-название.test.mjs`. Старые миграции не
   трогать. Так этапы не мешают друг другу.
3. Каждая миграция безопасна при повторном запуске.
4. Любое правило из ТЗ, которое этап добавляет в базу, повторить в `js/admin/demo.js`,
   чтобы демо-режим вёл себя так же.
5. Закончить: все тесты зелёные (`node supabase/test/run.mjs`), строка этапа в таблице
   ниже отмечена «готово» с датой, коммит. В `main` не пушить — пуш публикует сайт.
6. Если по ходу нашлось решение, которого нет в ТЗ, — спросить, а не придумывать.
